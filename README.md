# JMComic Next

为 JMComic 打造更清爽的网页体验，融入本地评分、个人偏好管理与 AI 个性化推荐。

## 项目介绍

JMComic Next 基于 [JMComic-Crawler-Python](https://github.com/hect0x7/JMComic-Crawler-Python) 提供的接口方案，重构 JMComic 的 WebUI，并围绕浏览、阅读、评价与发现作品完善交互体验。

项目采用 HTML、CSS、JavaScript 前端与 Python 本地服务。浏览器负责页面展示和交互，本地服务负责接口转发、账号配置、数据保存与推荐计算。当前代码自行实现接口调用，无需安装 `jmcomic` Python 包。

## 功能概览

- **清爽的 WebUI**：重新设计首页、分类、搜索、详情与阅读页面，适配桌面和移动端。
- **连续阅读体验**：支持浏览器直连图源、附近页面按需加载、失败换线重试与阅读进度记录。
- **本地评分与偏好**：保存 1–10 分总评、评语、标签偏好，以及封面、标题、作者等维度的兴趣反馈。
- **AI 个性化推荐**：结合个人评分、内容证据与可选 Qwen 多模态向量，在本地计算推荐排序。
- **可选 LLM 增强**：支持内容证据提取、作品内容分析、画像概述与标题翻译。
- **账号功能整合**：提供收藏、消息、追踪与手动签到入口。

## 数据与发布版本

仓库仅包含源码、界面资源和测试文件。账号密码、API Key、个人评分、收藏快照、阅读记录、用户画像及缓存均不随源码发布；`project/data/` 和 `project/.runtime-cache/` 会在运行时按需创建，并已整目录加入 `.gitignore`。

本地评分和阅读数据保存在自己的电脑上。AI 功能需要远程服务：Qwen 多模态请求会发送封面 URL 和标题，可选 LLM 功能会发送处理所需的相关文本；配置远程 API 后，按实际使用情况可能产生服务费用。

## 本地运行

准备 Python 3.10 或更新版本，并确保 PATH 中可以使用 `openssl` 命令。在项目根目录运行：

```bash
python3 local_server.py
```

也可使用 uv 按锁文件创建环境并启动（`.python-version` 选择 Python 3.13）：

```bash
uv sync --locked
uv run --locked python local_server.py
```

访问 `http://127.0.0.1:8000/`，按 `Ctrl+C` 停止。端口被占用时可追加 `--port 8001`。默认仅监听本机，请保持此设置。

项目只使用 Python 标准库，无需前端构建或安装第三方 Python 包。不要使用 `python3 -m http.server`，它无法提供本地 API。Node.js 仅用于开发测试，要求 22 及以上，`.node-version` 选择 24。迁移电脑时不要复制 `.venv`，应重新创建环境。

## 浏览器兼容

V2 前端以现代 iPhone Safari、Mac Safari 和 iPad Safari 为优先目标，保持原生 HTML/CSS/JavaScript，无需构建或安装前端依赖。统一深色主题使用低对比表面、细分隔线与黄色操作强调。

iPhone 竖屏使用顶部菜单入口，导航从左侧滑入并覆盖全屏；搜索、筛选、账号与阅读设置打开底部弹层；iPad 竖屏和手机横屏使用窄侧栏，宽屏使用完整侧栏。阅读页独立布局：返回、标题、目录、页码与图片设置合并在同一个底部工具栏，点击正文切换专注模式；键盘聚焦正文后按空格也可切换，Escape 恢复工具栏。目录、页码跳转和图片设置均可通过弹层操作；键盘 J / K 跳到下一页 / 上一页。

布局使用安全区、动态视口和 VisualViewport 处理浏览器工具栏及软键盘空间，弹层管理背景滚动与焦点；支持减少动态效果和减少透明度偏好。手机导航处于正常页面流中，不固定在视口边缘；阅读页底部面板四周留空，安全区留在面板外侧，避免整条深色背景延伸到 Safari 浏览器栏。移动端不指定固定的浏览器主题色；阅读器面板使用半透明灰色背景，减少透明度模式下保持不透明，不对漫画滚动区域做背景模糊，专注模式完全隐藏工具栏。iOS WebKit 使用更保守的图片内存窗口，并以分片 Canvas 还原图片。WebKit 的尺寸模拟不能替代真机 Safari 的软键盘、安全区和浏览器栏检查。

```text

```

该文件以明文保存密码，只应在自己的电脑上使用。服务器默认仅监听 `127.0.0.1`，请不要把监听地址改成局域网或公网地址。账号配置文件已加入 `.gitignore`。

## AI 推荐

推荐使用本地确定性模型 `personal-content-v2`。**7 分是喜欢门槛**：7–10 分作为喜欢样本，6 分作为关键对照，1–5 分作为未达门槛样本；6 分不等于讨厌，更不会产生硬屏蔽。评分原值保留，高评分样本保留更强的训练权重。未评分收藏不是负例，也不自动当作喜欢样本。

历史点击、完读、重读次数不参与偏好训练，避免开发期操作污染。明确标签反馈和 `overall/cover/title/tag_mix/author` 五维反馈仍有效，作用受限；有总评分时不再叠加同作品的整体印象。只有明确标签硬屏蔽会过滤作品。新鲜度、真实曝光衰减和作者多样性在内容排序后调整。

配置可选语言模型后，点击推荐会在预算内交替补充历史评分作品和候选的标题、简介、评论证据。默认上限48本，可设置0–500；0表示不新增远程分析。每本最多取两页评论、调用一次语言模型，最多3本并行；模型调用超时120秒。停止按钮停止新请求，已发出的调用可能仍完成并产生费用，完成的证据保留。

内容提取不传入你的评分、评语或收藏状态。每个语义特征必须附带可核对的原文片段；未知不能记为0，只赞画风不能推断内容无聊。评论总数、实际抓取数分别保存，但评论数量不进入排序。内容证据缓存保存在 SQLite 的 `content_evidence` 表，按输入、模型和处理版本识别；成功评论缓存7天，失败或未抓取状态30分钟后可重试。模型变化会使旧语义证据失效。缺评论、没有配置模型、模型失败或缺向量都不淘汰候选。

排序采用带正则约束、类别平衡的轻量逻辑回归；对标题/评论内容特征、训练集标签和作者、已有封面/标题/联合向量学习关联。缺失语义值按训练均值处理，不作为负面信号。推荐分是排序用途的分数，**不是校准后的喜欢概率**。历史评分未同时包含门槛两侧时使用探索排序，页面会说明证据不足。

Qwen 向量现在是可选辅助，不是生成推荐的前置条件。已有向量可复用，保存实际评价或开始阅读时仍可按原配置后台生成；生成推荐不再为全部候选强制调用 Qwen。无需第三方 Python 包、前端构建器或本地模型。

首次启动新版会一次性清理旧推荐结果及其曝光记录，解除反馈与旧推荐记录的关联，并删除可重建的画像快照。**评分、收藏、评语、标签反馈、五维反馈、阅读记录和账号配置不删除。** 新推荐历史只使用一种结构，不转换旧结果、不提供旧推荐算法开关。

离线评测（只读数据库，不启动服务、不调用远端）：

```bash
uv run --locked python tests/evaluate_recommender.py \
  --database project/data/user_library.sqlite3 \
  --output jm-recommender-evaluation.json
```

评测在作品版本/系列分组及作者分组下分别做3组固定种子的5折验证，报告7+对6分的AUC、前10/20命中率、NDCG排序质量及各折范围；特征词表与预处理只在训练折拟合。历史数据已经参与过探索，回顾性验证不能代替未来新评分的验证。标题/评论证据尚未补齐时不能据此宣称新模型效果提升。可选 `--baseline-module /path/to/archived_local_features.py` 仅用于一次性离线对照，旧模块只接触临时训练数据库，不进入运行服务。

### 统一的作品内容分析

只有已评分作品会在保存评分或更新评语后自动排队分析。评分先保存，后台使用与推荐流程相同的 `ContentEvidence` 分析器：输入标题、获取的简介/读者评论以及用户评语；数值评分仅用于本地训练和失效检测，不发送给 LLM。后台分析先获取作品简介与最多两页评论，获取失败时保留评价并标记失败，避免用空材料调用模型。远端确实没有简介或评论时才按未知处理。分析返回具体内容概括、七个内容维度及原文引用，验证后的维度直接供推荐模型使用。

详情页/阅读页“我的评价 → LLM 内容分析”展示内容概括、参与排序的维度数值/来源/引用，不展示原始 JSON。设置页只列出待处理项目，已完成项目仅计入统计。未通过原文核验的判断不参与排序。设置中的“补全／更新内容分析”只扫描已评分作品，补齐缺失、失败、评分/评语或模型/分析版本改变的记录；未评分的收藏不调用 LLM。没有变化的有效分析跳过，重复任务合并，旧请求不能覆盖新评价。失败不影响评分、评语或收藏；服务重启后未完成记录可再次补全。

仅保留 `content_evidence` 一份分析结果，旧的独立评分总结表在启动时删除，旧版本内容分析失效后可重建；不删除评分、收藏或评语。推荐页保留原先的候选收集、两页评论获取、分析额度、缓存刷新和排序流程；这条入口和评分后的后台任务共用分析缓存及每本作品的调用锁。已有分析直接用于排序，推荐时更新的分析也可在作品评价区查看。内容概括用于展示，排序继续使用原来的七维特征、标签、作者和向量。

### 配置 Qwen Embedding API

在百炼控制台创建 API Key，然后通过“设置 → Qwen 多模态向量”保存并测试。若下载的是业务空间配置，还要把 CSV 中的 `dashScope` 地址完整复制到 `DashScope Base URL`；`sk-ws-...` 工作空间 Key 不能发送给默认公共 Host。配置写入：

```text
project/data/qwen_embedding.json
```

也可以不写配置文件，直接使用环境变量：

```bash
DASHSCOPE_API_KEY=sk-... \
DASHSCOPE_API_BASE_URL=https://你的业务空间Host/api/v1 \
uv run --locked python local_server.py
```

API Key 只保存在本机且不会通过配置读取接口回传浏览器。`qwen3-vl-embedding` 当前固定使用 1024 维；若以后更换模型或维度，已有向量会因版本不匹配而自动重算。

### LLM 的职责

OpenAI 兼容 LLM 是可选增强，不参与最终打分。它负责提取标题/简介/评论的可核验内容特征、生成可读偏好概述，以及按需翻译标题。画像内的评语标签提取只用于叙述，不再作为权威评分输入。LLM 不输出最终推荐分，不覆盖手工反馈、不产生硬屏蔽。

如需这些增强，在“设置 → 语言模型（可选）”填写 API Key、Base URL 和模型名称。Base URL 应填写到兼容 API 的版本根路径，例如 `https://example.com/v1`；远程地址必须使用 HTTPS，本机 `localhost` 或 `127.0.0.1` 可以使用 HTTP。没有这项配置时，结构化画像和推荐仍可正常工作。配置写入 `project/data/ai.json`，API Key 不会通过本地 HTTP 接口回传给浏览器。

总评分、评语、逐项标签反馈、同步后的收藏、真实曝光与阅读行为、向量来源记录和推荐反馈保存在 `project/data/user_library.sqlite3`；可读画像快照保存在 `project/data/user_profile.json`。这些文件均已加入 `.gitignore`。实时排序直接从 SQLite 原始证据重建偏好模型，因此新增评价无需等待 LLM 才会生效。

漫画详情页和阅读页都只设置一个 1–10 分总评：1–2 分表示垃圾作品、看了浪费时间，3–4 分表示有严重雷点，5–6 分表示中规中矩，7–8 分表示整体及格且有亮点，9–10 分表示全方面优秀。标签按“未表态、喜欢、软回避、硬屏蔽”循环；总评不会自动传播成对全部标签的喜欢。手工标签偏好的方向取该标签全部当前反馈的平均值，置信度从首次反馈的 0.65 随独立作品样本数递增并在 0.95 饱和；因此一致反馈会逐步增强，但高频标签不会无限放大。硬屏蔽不等待置信度累积，仍会立即过滤候选。

推荐页支持关键字、分类、时间、连载过滤、候选池和最终数量。关键字只用于 JM 初筛，不参与个性化加分。推荐曝光只有在卡片至少 45% 进入视口后才记录；打开详情和开始阅读仍分别记录，但不训练偏好。感兴趣与否只在漫画详情页设置，`overall/cover/title/tag_mix/author` 五个维度分别保存一条当前状态；修改同一维度会覆盖旧状态，再次点击已选项会取消并删除该维度的当前状态，不同维度可以同时生效。只有“整体观感·不感兴趣”会直接增加该漫画的重复惩罚，取消或改选后会同步撤销这条反馈产生的惩罚；其他维度只训练对应特征。近期真实曝光会产生随时间衰减的重复惩罚，而不是永久排除。

可选 LLM 返回的画像补充要求结构化 JSON。程序会尝试本地解析并至多自动整理一次；LLM 失败不会阻止本地推荐。AI 标题翻译开关仍在账号配置窗口中，关闭时继续使用原有翻译接口。

登录成功后，Python 服务会把 AVS 会话保存在当前进程的内存中；切换页面不会重新登录。收藏、消息和追踪等受限请求统一由本地服务转发。如果远端返回 401，本地服务会串行执行一次重新登录并只重试该请求一次，避免多个并发请求重复登录。重启 Python 服务后，首次账号请求会读取配置并重新建立一次会话；会话令牌不会写入磁盘，保存的密码也不会通过本地 HTTP 接口回传给浏览器。

签到只会在点击导航栏“签到”按钮后触发。每次点击会先实时读取当前签到活动 ID，再携带账号 ID 和活动 ID 发送签到请求；签到状态不会读取或写入本地缓存。只有远端明确返回业务成功状态或“签到成功”消息时才显示成功，并保留奖励信息；“今天已签到”单独提示，不再显示失败。经验奖励文本本身不作为成功依据。读取活动失败会说明尚未提交；提交超时、断网、解密失败或响应无法判定时提示“结果未确认”，因为远端可能已经处理成功，不会自动重发。错误提示保留接口原因和状态。同一账号的并发点击共用正在进行的请求，请求结束后可再次点击确认。

阅读器由浏览器直连图源，并发数可选 1、2、5、10、20、50、100，默认 5，仅保存在当前设备的浏览器中。图片线路切换立即重新加载附近页面。

章节名称优先使用移动 API；多章节作品中名称为空的章节会由本地服务读取 JM 网页详情补全，网页端仍为空时显示“第N话”。单章节作品统一显示“全1话”。网页章节名称在本地缓存 24 小时。

正文图片直接从图源进入浏览器，不经过 Python 服务；不再提供服务端图片代理、整章预取或磁盘图片缓存。优先加载当前页及附近页面，离开附近范围会取消加载并释放图片或 Canvas，保留等高占位。每条线路最多等待 15 秒，失败自动切换备用线路；全部失败后可手动重试。不会自动回退到服务器转发。

附近解码内容的估算预算在 macOS Safari 中为 160 MB、iOS WebKit 中为 112 MB，其他浏览器为 256 MB；这不是整个标签页的内存上限。图片分片还原仍在前端完成，GIF 保留动画。离开阅读页停止任务，Safari 前进后退返回后重新加载附近页面。浏览器根据图源响应管理 HTTP 缓存，不承诺离线可用或固定保留时间；不同设备分别下载。

原有 `project/.runtime-cache/images/` 和 `project/data/settings.json` 不再使用，升级不会自动删除旧文件。账号、收藏、历史记录、评分及 AI 推荐仍通过 Python 服务处理。

## 缓存与清理

接口缓存写入：

```text
project/.runtime-cache/api/
```

缓存规则：

- 相册资料最长缓存 7 天
- 章节资料最长缓存 3 天
- 分类和首页推荐最长缓存 1 天
- API 线路清单缓存 6 小时，失效时会自动重新获取
- 单本收藏状态缓存 30 分钟，收藏状态改变后立即更新
- 单本喜欢状态缓存 30 分钟，喜欢状态改变后立即更新
- 收藏编号快照缓存 6 小时，收藏状态改变后立即更新
- 消息未读数缓存 1 分钟，消息状态改变后立即失效
- 总计最多 1200 项或 64 MB
- 本地服务启动时自动清理过期内容
- 每写入 25 次再次清理
- 超出数量或容量时，优先删除最久未使用的缓存

因此浏览缓存不会无限增长。若要清理服务器接口缓存，可删除 `project/.runtime-cache/api/`；下次启动和访问时会按需重新创建。推荐向量和反馈数据位于 `project/data/user_library.sqlite3`，不在浏览缓存目录中。

## 阅读与随机历史的保存和迁移

最近阅读和随机历史统一保存在 `project/data/user_library.sqlite3`，同一服务的不同浏览器在加载页面时读取同一份记录。历史按作品编号去重、按最后记录时间排序，数据库不再按旧浏览器的 100/200 条上限截断。清空历史会清空服务端对应列表。

打开首页、资料库或阅读页时，会自动将当前网址下的旧浏览器历史合并到数据库；较新的记录优先，导入成功才移除对应旧记录，失败可重试。也可打开 `/history-migration.html` 手动导入并查看数量，该页面不会调用账号或 AI 接口。不同浏览器、域名和端口的旧记录需要分别在原来的地址打开页面导入。

迁移电脑前先完成旧浏览器历史导入，停止服务，再复制完整 `project/data/`。不要复制 `.venv`；在目标电脑重建运行环境。上次阅读章节和图片线路选择仍属于各浏览器自己的设置。

### 远程访问时的推荐任务恢复

初筛完成后，浏览器先将候选和参数保存在当前站点的本地存储，再携带固定任务编号提交。服务器将任务写入 `project/data/recommendation_jobs.sqlite3` 后才确认接收；网络超时或确认响应丢失时，前端以同一编号自动重试（1–15 秒退避），不会重复创建同一任务。只有收到匹配的确认后才移除浏览器中的候选副本，任务编号继续保留。参数被拒绝时保留缓存并显示错误，不会无限重试无效请求。

评论仍由浏览器收集，最多三本并行、每本两页；每本提交后由服务器确认，刷新后跳过已接收部分。评论收集期间关闭页面会暂停收集，重新进入推荐页后继续。评论全部接收后，内容分析和排序由后台独立执行，关闭页面、刷新或客户端断网都不会取消已启动的后台任务。推荐页每约 1.5 秒查询任务状态，显示分析进度、失败数量、排序阶段和完成结果；断网时显示状态尚未确认并自动重连。停止操作也会保存在浏览器中，恢复连接后补发；已发出的分析可能继续完成并计费。

服务器重启后，等待评论的任务可以继续；执行中的任务会标记为“中断”，不会自动重做可能已计费的调用。若恰好在保存最终结果时中断，请先查看推荐历史。浏览器本地缓存依赖同一浏览器和站点地址；不要在交接尚未确认时清除站点数据。任务数据库包含候选、评论和结果，需随用户资料备份，已由现有 SQLite 忽略规则排除出 Git。此版本保留任务记录，不自动清理。

可靠性回归：`uv run --locked python -m unittest test_recommendation_jobs -q` 和 `node --test tests/recommendation_task.test.mjs`，均使用隔离数据及网络替身。
